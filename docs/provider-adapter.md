# Host provider adapter preparation

`recursa.provider.ProviderAdapter` implements a host-only, non-streaming Chat Completions transport. It is **not connected to the container runner, batch CLI or public server**. The runner still accepts only the concrete `OfflineBroker`. No genuine request has been executed. Focused tests replace the HTTP transport with `httpx.MockTransport` and use a fake credential.

Construction requires `authorize_live=True` and exactly five owner-controlled configuration fields: `base_url`, `api_key_env`, `rates`, `budget`, and `output_tokens`. Rates map allowlisted model names to input/output USD-per-million estimates. The budget uses the existing `CallBudget` schema. Remote rates must be positive. Endpoints permit HTTPS or loopback HTTP, without embedded credentials, queries or fragments. Configuration is copied, and construction performs no credential lookup or network I/O.

At completion time, only an allowlisted model and bounded text messages are accepted. The credential is read from the named host environment variable; missing credentials fail before reservation or dispatch. Each request reserves calls, input bytes, output allowance and estimated cost before opening the transport. The transport disables retries, redirects and environment proxies/certificate overrides. It sends fixed `max_completion_tokens`, `stream=false` and `store=false` fields. These fields follow the [official Chat Completions reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create); compatibility with any particular provider/model remains unverified.

Responses are limited to 128 KiB, uncompressed, with one completed assistant text choice of at most 64 KiB. Tool calls, refusals, truncated completions, missing/invalid token usage and overruns close the adapter. HTTP/transport errors also close it, retaining the reservation; there is no automatic retry after an uncertain charge. Provider-reported usage remains distinct from independently measured usage. A higher reported cost estimate consumes additional future headroom; lower reported estimates never refund reservations. Actual billing remains null. These estimates cannot guarantee a provider's invoice or prevent a provider from exceeding its requested output cap.

Sanitized summaries contain prompt/response hashes, reservations, usage counts and classification codes. They exclude credentials, endpoint URLs, raw messages, raw response text and error bodies. Adapter state is serialized under a lock, and returned summaries are copied. Replay imports need no optional HTTP dependency.

The base adapter checks the elapsed deadline around dispatch and between response chunks, with each HTTP operation capped at the remaining time or 30 seconds. Its direct path cannot preempt a blocked operation. Use the supervised host path described below for a process lifetime boundary. Neither path is a sandbox.

## Supervised host path

`recursa.provider_worker.SupervisedProviderAdapter` requires the same explicit authorization and configuration, plus a fresh private output directory. The parent owns the shared budget across calls and reserves before releasing each stdin-gated worker. Each worker gets at most one completion. A worker restart cannot reset the parent budget. Credentials remain in the inherited host environment; they are never serialized into stdin or output records. This is a trusted host worker, separate from the generated-code container.

On Windows, the existing kill-on-close job attaches before stdin is released. Timeout, cancellation and normal exit clean up the worker and descendants. The POSIX process-group path exists but has not been verified on this Windows development machine. Parent-side deadlines cover process startup and the whole blocked transport; cleanup and durable reporting can add time after the execution deadline. Killing the worker cannot cancel a request already accepted by a remote provider or prove it was unbilled.

Each call saves `reservation.json` before dispatch, a parent-observed `worker-report.json`, and a bounded private `response.json` when the worker finishes. The session retains a sanitized `session-report.json` on success, failure and cancellation. Raw prompts, endpoint URLs and credential values are excluded from these records; returned source/text remains private in `response.json`. Never publish this output directory. A timeout or uncertain result retains its reservation and closes the adapter. Missing, malformed and oversized result files are rejected, and the parent independently rechecks returned text and usage. A record-writing failure also closes the session.

Seven focused supervisor checks cover actual intercepted worker success, parent budget preservation, HTTP failure, blocked-transport timeout with descendant cleanup, cancellation with durable partial records, missing authorization/credentials, boundary failure, corrupt results, parent usage revalidation and record-write failure. These are regression cases, not genuine inference evidence.

## Remaining gate

The next integration must connect host request validation to the supervised adapter, preserve the existing concrete offline path, and export private traces safely. Provider failures currently retain conservative parent reservations; provider usage from a failed or interrupted worker can remain unknown. An actual run additionally requires explicit owner authorization, a selected endpoint/model, configured credentials and a spending cap. Generic “continue” messages authorize continued offline engineering only. No model-backed P0 or research claim follows from these intercepted tests.
